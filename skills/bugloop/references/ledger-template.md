# Ledger schema

One ledger = one bug = one file, at
`~/.claude/bugloop/<project-slug>/<date>-<slug>.md`. `<project-slug>` is
`basename(project_dir)-<8 char hash of absolute path>`, so two different
repos both named `api` never collide.

Generated by `bugloop.sh init "<desc>"`. Fields are flat `key: value` lines
(dotted names like `repro.test_cmd` are literal field names, not nesting) so
`get_field`/`set` can find them with a single grep/awk pass. Section headers
(`## repro`, `## baseline`, ...) are for human/model readability only — the
engine does not parse them.

```markdown
# Bug: <one-line description>

state: TRIAGE                      # TRIAGE|REPRO|LOCATE|HYPOTHESIZE|PATCH|
                                    # VERIFY|REVIEW|LANDED|UNREPRODUCED|
                                    # FLAKY|ARCHITECTURE_QUESTION|
                                    # BLOCKED_NEEDS_HUMAN
project_dir: /abs/path
created_at: <ISO 8601 UTC>
test_cmd: <auto-detected or UNKNOWN>

## repro
repro.test_path:                   # path to the failing test file
repro.test_cmd:                    # command that runs just this test
repro.failing_output:              # literal output, condensed to one line

## baseline
baseline.captured_at:              # ISO timestamp — set by `bugloop.sh baseline`
baseline.failing_tests:            # summary of what already failed pre-fix

## locate
locate.sites:                      # "path:line, path:line, ..." — defs + callers

## hypotheses
- [1] status=testing :: <cause statement> :: <evidence> :: <falsifier>
<!-- one line per hypothesis; refuted ones stay, marked status=refuted -->

## patch
patch.files_changed:               # comma-separated paths actually edited

## verify
verify.focused: PASS|FAIL
verify.baseline_diff: CLEAN|<description of new failures>

## review
review.verdict:                    # from cavecrew-reviewer or main thread

## receipts
<!-- `bugloop.sh receipt "<cmd>"` appends a timestamped block here:
### <ISO timestamp> — `<cmd>` — exit <code>
```
<last 40 lines of output>
```
-->
```

## Rules for editing the ledger directly

- The `## hypotheses` and `## receipts` sections are free-form append —
  edit them with the Edit tool, not `bugloop.sh set`.
- Every other field is single-line — use `bugloop.sh set <field> "<value>"`,
  which does an atomic write (temp file + mv), so a crash mid-write never
  corrupts the ledger.
- Never delete a refuted hypothesis or an old receipt. The ledger is a
  record, not a scratchpad — that's what makes it survive `/clear`.
